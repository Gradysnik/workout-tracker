# Workout Tracker — дизайн

Дата: 2026-11-15. Статус: одобрен 2026-11-15.

## Зачем

Сейчас тренировки ведутся в Google-таблице «Yury Workouts»: строки — упражнения трёх дней (ВТ/ЧТ/СБ), колонки — недели, в ячейке подходы в виде `вес.повторы`, дроп-сеты через дефис. С этим три проблемы:

1. **Захламлённость.** Видны все 25 упражнений и 36 недель сразу, а нужен только сегодняшний день.
2. **Замена упражнений.** При замене упражнения в строке прогресс старого продолжается под новым названием.
3. **Ввод с телефона.** Набирать `40.10\n55.10` в ячейке неудобно.

При этом таблица даёт то, что терять нельзя: правки с ноутбука, вопросы Gemini по прогрессу и свободу самому составлять программу и расписание.

## Цели

- Экран «Сегодня» показывает только упражнения текущей тренировки.
- По каждому упражнению есть свой прогресс: график и список прошлых тренировок.
- Замена упражнения начинает прогресс с нуля, старое упражнение остаётся в истории.
- Ввод подхода — одно касание, если вес и повторы не изменились.
- Данные синхронизируются с Google-таблицей в формате, удобном для чтения человеком и Gemini.
- Программа и расписание задаются пользователем в таблице.
- Результат — APK-файл, код хранится в `github.com/Gradysnik/workout-tracker`.

## Не цели (в первой версии)

- Редактирование программы и расписания в приложении. Запланировано как следующая фича, структура данных должна это допускать.
- Публикация в Google Play, сборка под iOS и веб.
- Правка журнала подходов с ноутбука с обратной синхронизацией в приложение.
- Несколько пользователей, таймер отдыха, уведомления.

## Анти-цели

- Приложение, которое не работает в зале без сети.
- Таблица в формате, который неудобно читать глазами или отдавать Gemini.
- Потеря уже накопленной истории с сентября 2025.

## Ограничения

- На ноутбуке разработки нет Android SDK и Java. APK собирается на GitHub Actions.
- Вход через Google требует проекта в Google Cloud Console, привязанного к отпечатку подписи APK. Это ручная разовая настройка владельцем аккаунта.
- Приложение личное, для одного человека.

## Подходы

| Подход | Плюсы | Минусы |
|---|---|---|
| **Flutter + сборка на GitHub Actions** (выбран) | Одна кодовая база для будущих iOS и веба; не нужен локальный Android SDK | Проверка на реальном Android только через собранный APK |
| Нативный Android (Kotlin + Compose) | Самое «родное» ощущение | Для iOS интерфейс придётся переписывать; нужна Android Studio |
| Веб-приложение в APK-обёртке | Быстрее всего | Ненадёжные вход через Google и офлайн, хуже ввод с телефона |

Выбран Flutter: пользователь допускает кросс-платформенность в будущем, а удобство ввода с телефона — главная боль.

Синхронизация: из трёх вариантов (правится только программа / правится всё / таблица только для чтения) пользователь выбрал первый. Журнал пишет только приложение, программу и расписание пользователь правит в таблице.

## Что решил пользователь

### Какая тренировка «сегодня»

- Расписание привязано к дням недели и задаётся в таблице.
- В день по расписанию открывается тренировка этого дня.
- Если последняя по расписанию тренировка пропущена, приложение предлагает её первой («Вторничная тренировка не выполнена — сделать сегодня?»). Тренировка текущего дня при этом остаётся доступной.
- Если пропущено больше одной тренировки, долги не копятся: предлагается тренировка текущего дня или ближайшая следующая. Пропущенные доступны вручную.
- В день без тренировки показывается ближайшая следующая, её можно начать досрочно.
- Любую тренировку можно выбрать вручную одним касанием.
- Каждая запись хранит фактическую дату занятия, а не плановую.
- Есть календарь истории: видно даты тренировок, любую можно открыть.

### Экраны

Макеты: `.superpowers/brainstorm/45956-1794737142/content/screens.html` (не в git).

1. **Сегодня.** Название тренировки, дата, счётчик выполненных. Список упражнений дня: название, цель (`4×8–10, дроп-сет`), результат прошлого раза. Выполненные отмечены галочкой.
2. **Ввод подхода.** Выбран вариант с крупными кнопками «плюс/минус» отдельно для веса и повторов. Значения подставлены из того же подхода прошлой тренировки. Касание по числу открывает клавиатуру для точного ввода. Кнопка «Готово», кнопка «+ часть дроп-сета», строка «Прошлый раз: …», переход к графику.
3. **Прогресс по упражнению.** График (макс. вес / объём / повторы) и список прошлых тренировок только по этому упражнению.

Нижняя навигация: «Сегодня», «История», «Программа».

### Замена упражнения

Прогресс привязан к упражнению. Пользователь меняет название в листе «Программа»: новое упражнение начинается с нуля, старое пропадает из программы, но остаётся в «Истории» со всем графиком.

## Формат таблицы

Приложение при первом входе само создаёт новую таблицу с тремя листами. Первая строка каждого листа — заголовки.

**«Программа»** — правит пользователь, приложение только читает.

| Тренировка | Порядок | Упражнение | Тип | Подходы | Повторы | Дроп-сет | Шаг веса | Заметка |
|---|---|---|---|---|---|---|---|---|
| Спина + Бицепс | 2 | Тяга верхнего блока к груди (широкий) | силовое | 4 | 8–10 | нет | 5 | |
| Грудь + Трицепс | 8 | Планка с подъёмом ног | время | 3 | 30–45 | нет | | секунды |
| Спина + Бицепс | 1 | Гребной тренажёр | кардио | 1 | | нет | | 5 минут |

**«Расписание»** — правит пользователь, приложение только читает.

| День недели | Тренировка |
|---|---|
| Вт | Спина + Бицепс |
| Чт | Грудь + Трицепс |
| Сб | Ноги + Кор |

**«Журнал»** — пишет приложение. Одна строка — одна часть подхода (у обычного подхода часть одна, у дроп-сета несколько).

| ID | Дата | Тренировка | Упражнение | Подход | Часть | Вес | Повторы | Секунды | Минуты | Ккал | Заметка |
|---|---|---|---|---|---|---|---|---|---|---|---|
| a1b2 | 2026-11-10 | Спина + Бицепс | Тяга горизонтального блока (узкий хват) | 4 | 1 | 60 | 10 | | | | |
| a1b3 | 2026-11-10 | Спина + Бицепс | Тяга горизонтального блока (узкий хват) | 4 | 2 | 40 | 10 | | | | |

Типы упражнений:

- **силовое** — вес и повторы, возможны части дроп-сета;
- **время** — секунды на подход (планка);
- **кардио** — минуты и ккал; наклон и скорость дорожки пишутся в заметку.

## Решения автора (не обсуждались, можно оспорить)

- **Стек:** Flutter (Dart), локальная база SQLite через `drift`, состояние через Riverpod, Google через `google_sign_in` и `googleapis` (Sheets v4).
- **Доступ к Google:** область `drive.file` — приложение видит только таблицу, которую само создало. Это не требует проверки приложения Google. Следствие: старую таблицу приложение прочитать не может, см. «Перенос истории». Проверить при реализации, что токен в таком режиме не истекает через 7 дней.
- **Офлайн:** источник правды для журнала — локальная база. Каждая запись ставится в очередь отправки и уходит в таблицу при появлении сети. Строки журнала находятся по колонке ID, поэтому исправление подхода в приложении обновляет ту же строку.
- **Чтение программы:** при запуске и по жесту «потянуть вниз». Последняя прочитанная версия хранится локально и работает без сети.
- **Идентичность упражнения — его название** (без учёта регистра и крайних пробелов). Следствие: исправление опечатки в названии создаст «новое» упражнение. Обходной путь — исправить название и в листе «Журнал» заменой по всей колонке, затем выполнить «Восстановить из таблицы».
- **Восстановить из таблицы:** пункт в настройках, который заново загружает журнал из таблицы в локальную базу. Нужен при переустановке, смене телефона и после переноса истории.
- **Перенос истории:** отдельный скрипт в репозитории (`tool/migrate`) разбирает CSV-выгрузку старой таблицы (`вес.повторы`, дефисы дроп-сетов, `64к`, `7%-5.5s`, `30.30.30`, заметки в скобках) и выдаёт строки для листа «Журнал». В колонке недели три даты сверху вниз соответствуют трём тренировкам. Пустые и нулевые (`0.0`) ячейки пропускаются. Прошлые замены упражнений в старой таблице не различимы: история ложится под нынешними названиями. Тот же скрипт выдаёт строки для листов «Программа» и «Расписание» из нынешних названий упражнений (цель `4×8–10, дроп-сет` разбирается из названия). Результат — три CSV-файла; пользователь один раз загружает их в созданную приложением таблицу с ноутбука (Файл → Импорт → Заменить текущий лист), затем выполняет «Восстановить из таблицы».
- **Пустая программа:** если лист «Программа» пуст, экран «Сегодня» показывает подсказку со ссылкой на таблицу, а не ошибку.
- **Шаг веса:** по умолчанию 2,5 кг, переопределяется колонкой «Шаг веса». Дробные веса допустимы.
- **Одна активная программа:** та, что записана в листах. Смена программы — правка листов.
- **Вкладка «Программа»** в первой версии показывает программу и расписание только для чтения.
- **Вкладка «История»:** календарь тренировок и список упражнений, которых больше нет в программе.
- **Интерфейс:** на русском, тёмная и светлая тема по системной настройке.
- **Цвета (согласовано с пользователем):** на Android 12+ акцентные цвета берутся из системной палитры (Material You, пакет `dynamic_color`); на более старых версиях — фиксированная палитра приложения с синим акцентом. Галочки «выполнено» и линия графика всегда в фиксированных цветах.
- **Локальная разработка (согласовано с пользователем):** на ноутбук ставится Flutter через Homebrew, без Android Studio. Тесты и проверка экранов идут локально (приложение запускается в браузере), APK по-прежнему собирает GitHub Actions.
- **Android:** минимальная версия 8.0 (API 26), идентификатор `com.gradysnik.workout_tracker`.
- **Сборка:** GitHub Actions собирает подписанный APK по тегу `v*` и прикладывает его к релизу. Ключ подписи хранится в секретах репозитория; его SHA-1 регистрируется в Google Cloud.
- **Тесты:** модульные на выбор тренировки дня, разбор старого формата, преобразование записей в строки таблицы и обратно, очередь синхронизации.
- **Инструкция** по настройке Google Cloud и секретов — `docs/setup.md`.
